# 轨道 Orbit · 产品设计

## 1. 背景

希望把生活中的待办、计划，以及后续的项目、学习、工作、衣食住行、情绪、人际等，收进同一个软件。一次做完「全能」风险极高，因此 **V1 只做发射台：今日待办与日计划**，用通知和桌面小组件保证天天能用上。

## 2. 定位

| 维度 | 决策 |
| --- | --- |
| 产品名 | 轨道 Orbit |
| 一句话 | 各条生活轨道围绕同一中心运转；V1 中心是「今天」 |
| 用户 | 先自己用；打磨后再考虑对外产品化 |
| 端 | 手机优先（iOS + Android）；V1 以 Android 为主要开发/验证端 |
| 数据 | 本地优先、隐私优先；V1 不做账号与云同步 |

## 3. 目标用户场景（V1）

1. 早上打开 App 或看桌面小组件，知道「今天要做什么」。
2. 随时记下一条待办，设好提醒，到点本地通知。
3. 晚上勾选完成，或把未完成项改期到明天。
4. 用简单分类（工作 / 学习 / 生活）区分轨道，不被复杂项目管理淹没。

## 4. V1 边界

### 4.1 V1 做（MVP）

| 能力 | 说明 |
| --- | --- |
| 待办 | 创建、编辑、删除、完成；标题、备注、计划日期、优先级、分类 |
| 日计划 | 按天查看与安排；有序列表或简单时间块（不过度做日历） |
| 提醒 | 到点本地通知；支持简单重复（如每天 / 工作日） |
| 分类 | 一级 list/tag，足以表达多条轨道，不做多层标签树 |
| 小组件 | 桌面展示今日未完成；Android 优先，支持快速勾选 |
| 导出 | JSON 全量导出，为迁移与以后同步留口 |

### 4.2 V1 不做

- 账号、登录、云同步、多设备实时协作
- 项目管理（甘特、任务树、依赖）
- 学习管理（间隔重复、课程进度）
- 工作薪资、财务记账
- 衣食住行流水、情绪、运动、人际等生活维度记录
- AI 助手、分享、社区
- Web / 桌面客户端

以上均进入后续里程碑，作为围绕 Orbit 的「卫星模块」，而不是 V1 的 Tab。

## 5. 里程碑

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 设计 | 名称、边界、栈、数据模型 | 本文档与 ARCHITECTURE / DATA_MODEL 定稿 |
| 脚手架 | Flutter 工程 + 目录 + 依赖 | `flutter create` 可分析、可跑空壳 |
| V1a | 待办 + 日计划 + 本地通知 + 分类 + 导出 | 自己连续多日真实使用 |
| V1b | 桌面小组件 + 交互打磨 | Android 桌面可看今日并勾选 |
| V2+ | 多端同步（本地 SQLite + 云端 PostgreSQL） | 按需启动，不在 V1 验收内 |
| 卫星模块 | 项目 / 学习 / 工作 / 生活记录等 | V1 用稳后单独立项 |

## 6. 成功标准（自用）

- 一天内打开并处理待办的次数稳定（习惯能留下）。
- 新增一条待办并设置提醒的路径短、不易出错。
- 桌面小组件信息够用，不必每次点进 App。
- 代码与数据结构可导出、可演进，不为 V1 过度设计。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 范围膨胀成「全能生活」 | 边界写死在本文档；新想法进 Backlog，不进 V1a |
| 与已有日记类应用重复建设 | 不合并进 V1；生活维度只作后续参考 |
| 小组件/ iOS 原生成本 | Android 先行；iOS 用 CI 或后补，不阻塞 V1a |
| 技术栈换到 Flutter 的上手成本 | 文档与目录约定先行；功能切小步交付 |
| 品类竞争激烈（滴答等） | 不比全能，比「今日中心」顺手与本地隐私 |

## 8. 产品原则

1. **中心是今天**：首屏服务「现在该做什么」。
2. **少而准**：V1 功能少，但完成、提醒、改期必须可靠。
3. **本地优先**：数据默认不出设备。
4. **可演进**：模型预留同步字段，UI 不提前堆模块。
5. **轨道可扩展**：分类/领域字段从第一天就存在，即使 V1 只有三类。

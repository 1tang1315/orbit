# 01 — 通用规范

> 适用于 Web（`web/hub/`）与 Flutter（`lib/`）的通用约定。特定于 Web 的规则见 [02-Web开发规范](./02-Web开发规范.md)，Flutter 见 [03-Flutter开发规范](./03-Flutter规范.md)。

## 1. 命名规则

### 1.1 文件命名

默认所有文件名使用 **kebab-case**（小写字母 + 连字符）。以下为明确例外：

| 类型 | 命名 | 示例 |
|---|---|---|
| 通用 TS/SCSS/JSON/MD 文件 | kebab-case | `actions.ts`、`tokens.scss`、`work-items.json` |
| **React 组件文件** | **PascalCase**（React 生态惯例） | `TaskCard.tsx`、`KanbanColumn.tsx` |
| Next.js 保留文件 | 框架规定，不可改 | `page.tsx`、`layout.tsx`、`route.ts`、`not-found.tsx` |
| Dart 文件 | snake_case（Dart 惯例） | `todo_controller.dart`、`plan_repository.dart` |
| 目录名 | kebab-case 或单词小写 | `work-items/`、`features/`、`components/` |

禁止：中文、空格、snake_case（Dart 除外）出现在非对应约定的文件名中。

```
✅ 正确:
task-card.tsx            （React 组件，PascalCase）
actions.ts               （业务域逻辑）
01-通用规范.md
todo_controller.dart     （Dart）

❌ 错误:
taskCard.tsx             （camelCase）
TaskCard.ts              （React 组件不省略 x / 用后缀）
任务卡片.tsx              （中文）
```

- 文件处于明确功能目录中时，**不必重复目录名**：`components/ui/badge.tsx` 不写 `badge-ui.tsx`。

### 1.2 变量与函数命名

- TypeScript / Dart 统一 **camelCase**（首字母小写）。

```typescript
const taskList: Task[] = [];
function formatDateTime(iso: string): string { ... }
```

```dart
final taskList = <Task>[];
String formatDateTime(DateTime iso) { ... }
```

### 1.3 常量命名

- 模块级常量统一 **UPPER_SNAKE_CASE**。

```typescript
const KANBAN_COLUMNS = ['planned', 'todo', 'doing', 'review', 'done'] as const;
const DEFAULT_PAGE_SIZE = 20;
```

### 1.4 类名、接口名与类型名

- class / interface / type / enum 一律 **PascalCase**，**不加 `I` 前缀**。

```typescript
interface Task { ... }          // ✅
interface ITask { ... }         // ❌
type SyncMode = 'full' | 'incremental';
class TaskCardProps { ... }     // 一般用 interface，少用 class
```

### 1.5 数据库与 seed 字段

- SQLite 表名、列名与 seed JSON 字段统一 **snake_case**（SQL 生态惯例，且与将来真实采集字段对齐）。
- TS 代码中一律 **camelCase**；snake_case → camelCase 的转换**集中在 `lib/db.ts` 的行映射**完成，禁止在业务代码里散落双字段兼容逻辑（`obj.task_id ?? obj.taskId` 一律禁止）。

## 2. 仓库目录结构

仓库根只放三大块，界限清晰：

```text
orbit/
  ├── lib/  android/  ios/  test/  pubspec.yaml   # Flutter 移动端
  ├── docs/                                       # 全部项目文档
  │   ├── PRODUCT.md / ARCHITECTURE.md / DATA_MODEL.md
  │   ├── DESIGN.md / AUTOMATION.md / HUB_PLAN.md
  │   └── 开发规范/                                # 本规范
  └── web/                                        # Web 工作区（容器 + 索引，一 Web 项目一子目录）
      ├── README.md                               # 工作区索引：登记各 Web 项目
      └── hub/                                    # 知识中枢 Next.js 全栈应用（自包含）
          ├── package.json / next.config.ts / tsconfig.json
          ├── public/       # 静态资源
          ├── app/          # 路由层（薄：只放官方约定文件）
          ├── features/     # 业务域：workspace / projects / tasks / work-items / knowledge
          ├── components/   # 跨业务通用 UI：shell / ui
          └── lib/          # db / seed
```

- **业务域目录（`features/<域>/`）= 前端组件 + 后端逻辑**，不按技术层横向拆分（详见 02 §1）。
- 文档只进 `docs/`，代码注释与 README 不承载长篇方案。
- 构建产物（`node_modules/`、`.next/`、`build/`、`.dart_tool/`）一律不入库，统一由 `.gitignore` 管理。

## 3. Import 顺序

### 3.1 TypeScript（`web/hub/`）

按以下顺序分组，**组间空一行**；同组内具名导入按**字母序**：

1. **Node / 浏览器内置模块**（`node:*`）
2. **第三方库**（`react`、`next/*` 等）
3. **项目别名**（`@/` —— 指向 `web/hub/` 根，覆盖 `features/`、`components/`、`lib/`）
4. **相对路径导入**（`./`、`../`）
5. **样式文件**（`.scss` / `.css`）

```typescript
// 1. 内置模块
import { DatabaseSync } from 'node:sqlite';

// 2. 第三方库
import { useTransition } from 'react';
import Link from 'next/link';

// 3. 项目别名
import { moveTaskStatus } from '@/features/tasks/actions';
import type { Task } from '@/features/tasks/types';
import { formatDate } from '@/components/ui/format';

// 4. 相对路径
import { TaskCard } from './TaskCard';

// 5. 样式
import './globals.scss';
```

- 单行导入优先；超过 **120 字符**或超过 **6 个具名项**时换多行。

### 3.2 Dart（Flutter）

按顺序分组，组间空一行：

1. `dart:` SDK
2. `package:` 第三方
3. `package:orbit/`（本项目）
4. 相对路径

```dart
import 'dart:async';

import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

import 'package:orbit/features/todo/todo_controller.dart';

import 'todo_list_tile.dart';
```

## 4. 注释规范

### 4.1 统一原则

- 注释使用**中文**。
- 注释解释"**为什么**"，代码解释"是什么"。
- 不写废话注释（如 `// 将计数加一`、`// 定义任务列表`）。
- 命名良好的代码可以不加注释；公共 API / 跨业务域的函数必须有 JSDoc。

### 4.2 函数注释（JSDoc / Dart doc）

```typescript
/**
 * 将任务移动到看板指定列。
 *
 * 除更新 status 外，会同步刷新 updated_at，并触发对应页面的数据重新验证。
 *
 * @param taskId - 任务稳定 ID
 * @param status - 目标状态，取值见 KANBAN_COLUMNS
 */
export async function moveTaskStatus(taskId: string, status: TaskStatus) { ... }
```

```dart
/// 按计划日期加载今日未完成待办，按 sort_order 升序。
///
/// 软删除（deleted_at 非空）的条目不参与查询。
Future<List<Todo>> loadTodayTodos(String day) async { ... }
```

### 4.3 区块注释

- 工具模块内使用 `// region 名称` / `// endregion` 做逻辑分组。

```typescript
// region 日期格式化

/** 将 ISO 字符串格式化为 YYYY-MM-DD。 */
export function formatDate(iso: string): string { ... }

// endregion
```

### 4.4 JSX / 模板注释

- 仅在上层容器或区块上方用一句简短注释标注区块，不写行内碎碎念。

```tsx
{/* 待复盘任务队列 */}
<section className="review-queue">...</section>
```

## 5. Git 提交规范

### 5.1 Commit Message 格式

```
<type>(<scope>): <subject>

[body]
```

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `refactor` | 代码重构（不改变功能） |
| `docs` | 文档更新 |
| `style` | 代码格式（不影响逻辑） |
| `chore` | 构建/工具/依赖变更 |
| `test` | 测试相关 |

**scope 约定**：`hub`（知识中枢 Web 应用，含公共层 `components` / `lib`）及业务域名（`workspace`、`projects`、`tasks`、`work-items`、`knowledge`）、`flutter`、`docs`、`规范`、`deps`。

```text
✅ 正确:
feat(tasks): 看板拖拽改为 Server Action 落库
fix(lib): 修复 seed 装载在 dev 热更时重复建表
docs(规范): 新增 Web 开发规范
chore(deps): 升级 next 至 15.x

❌ 错误:
update code
修改了一些东西
bug fix
```

> 存量提交不追改；自本规范生效起遵循上述格式。subject 用中文。

### 5.2 分支命名

- 功能分支：`feat/<kebab-description>`，如 `feat/kanban-drag`
- 修复分支：`fix/<kebab-description>`

## 6. 时间与 ID 约定

与 `docs/DATA_MODEL.md` 保持一致，Web 端复用同一套约定：

| 项 | 约定 |
|---|---|
| 稳定 ID | 客户端生成 UUID 字符串，不依赖自增主键 |
| 入库时间 | 一律 UTC ISO-8601（`2026-09-28T12:00:00Z`），展示层转本地时区 |
| 软删除 | `deleted_at` 非空表示已删，默认查询过滤 |
| 日期（日粒度） | `YYYY-MM-DD` 本地日字符串（如 `scheduled_for`、`day`） |

## 7. UI 文案

- 界面文案默认中文；日期、数字格式化统一走 `Intl` / `intl` 包，不手拼字符串。
- 状态语义两套语言不混用（DESIGN.md §5）：**来源标签**（紫=需求、红=Bug）回答"从哪来"；**状态色**（橙=待确认、绿=完成）回答"到哪步"。
